# Fynona client

Flutter client of Fynona, a personal finance service. The client only visualizes
the Fynona API: amounts, totals and aggregates come from the server.

Targets: Android, iOS, web, Linux, macOS, Windows.

## Layout

| Path | What it is |
|---|---|
| `lib/` | The app: shell (navigation, profile switcher), placeholder screens, settings, localizations |
| `lib/l10n/app_{uk,ru,en}.arb` | UI strings; `lib/l10n/gen/` is generated by `flutter gen-l10n` (committed) |
| `packages/fynona_ui/` | Design system package: tokens, themes, glass chrome, navigation components |
| `api/openapi.yaml` | Copy of the server's public spec (never edited here; the root repository keeps it in sync) |
| `packages/fynona_core/` | Pure Dart network core shared with the admin client: transport, errors, contract check, session, wire decimal; no API path (see its README) |
| `packages/fynona_api/` | Pure Dart public API package: models generated from `api/openapi.yaml` and the public routes and rules over `fynona_core`, which it re-exports (see its README) |
| `test/` | Widget tests: work zone, semantics, localization, glass modes, source rules, goldens |

## Stack

Flutter 3.50.0 (pinned in `.github/workflows/ci.yml`), `material_ui`, Riverpod 3
without code generation, `go_router`.

## Commands

```sh
flutter pub get
dart format --set-exit-if-changed .
flutter analyze
flutter test                                  # app tests incl. goldens
(cd packages/fynona_ui && flutter analyze && flutter test)
(cd packages/fynona_core && dart analyze && dart test)
(cd packages/fynona_api && dart run swagger_parser && dart analyze && dart test)
flutter build web --dart-define=FYNONA_API_URL=https://…   # or linux, apk, ios, macos, windows
```

Without `FYNONA_API_URL` the app calls its own origin. While a circuit breaker of
the transport is open, the shell shows a «no connection» banner.

On start and on every resume the app compares its contract version with
`GET /v1/meta` (API-12, `lib/api/contract.dart`). An outdated client (another
major, below `min_contract_version`, `/v1/meta` 404 or 410, any
`426 api_version_unsupported`) gets a blocking «update the app» screen, with a
reload button on web; a server whose contract minor is behind the client's gets a
blocking «the service is updating» screen with a retry button. No connection or a
malformed server version never blocks.

## Sign-in (SEC-1…SEC-5)

`lib/auth/` holds the session, `lib/screens/auth/` the screens: sign up, «check
your email» (no resend: the API has no route for it, so the screen points to the
spam folder and a new sign-up), the emailed links (`/verify-email?token=…`,
`/reset-password?token=…`), forgot password, sign in, the second factor (a sign-in
with TOTP on answers `202`; a TOTP or recovery code completes it through
`POST /v1/auth/login/mfa`) and passkey sign-in on web. A wrong email and a wrong
password read the same. The router guard (`lib/shell/router.dart`) shows only these
routes while signed out and the app shell once signed in; on start the app resumes
the saved session before deciding.

Tokens: on Android, iOS, macOS, Windows and Linux the refresh token lives in
`flutter_secure_storage` (Linux builds need `libsecret-1-dev`); on web the server
keeps it in the httpOnly `fynona_refresh` cookie and the access token stays only in
memory, so the API must be on the same site as the web app and allow its origin.
A `401` refreshes the tokens once (parallel requests share one refresh) and repeats
the request; a refused refresh signs out. Signing out (Ще) ends the session on the
server and clears the stored token, the in-memory token and the cached account.

## Account, security and plan (CLI-12, SEC-60, MON-3, MON-4)

Under Ще (`lib/screens/account/`, providers in `lib/account/account.dart`):
Безпека lists the sessions (device, IP, last use, «this device») and ends one or all
others; turns TOTP on (QR code drawn with the `qr` package, manual key, first code),
shows the recovery codes once with copy and save, issues new ones and turns TOTP off
with a code or the password; on web it adds, lists and deletes passkeys. Акаунт edits
the display name, language and display currency with `If-Match` (a `412` reloads),
asks for an email change with re-authentication and shows the pending address,
starts an export, follows it and saves the archive (browser download on web, the
Downloads or documents folder elsewhere, through `path_provider`), and deletes the
account after re-authentication and typing the account's email. Підписка shows the
plan and entitlements of `GET /v1/entitlements`, for display only. Any
`402 entitlement.exceeded` opens a plan-offer sheet naming the entitlement and the
plans that give more of it (`lib/app.dart`, `ApiTransport.entitlementRejections`).

Goldens are rendered on Linux; refresh them after a deliberate visual change with
`flutter test --update-goldens test/golden_test.dart`.

## Rules checked by tests

- Work zone: on Операції the list takes at least 60 % of the window height at
  first and at least 85 % after scrolling, at 320×568, 360×640 and 390×844 with
  text scale 1.0 and 2.0 (`test/work_zone_test.dart`).
- No user-facing string literals in widgets and no left/right layout
  (`test/source_rules_test.dart`).
- Every interactive element has a screen-reader label (`test/semantics_test.dart`).
